## Мета уроку

Зрозуміти, як EF Core створює екземпляри сутностей під час завантаження даних із бази (матеріалізації), які правила діють для параметризованих конструкторів і які є обмеження щодо навігаційних властивостей.

## Теоретичний матеріал

За замовчуванням під час читання рядка з БД EF Core викликає конструктор без параметрів, а потім заповнює властивості об'єкта. Проте якщо клас визначає **конструктор із параметрами**, EF Core може передавати значення стовпців безпосередньо в цей конструктор.

### Основні правила для конструкторів у EF Core

- **Відповідність імен та типів:** назви й типи параметрів конструктора мають відповідати властивостям сутності (регістр літер не має значення, наприклад, властивість `Name` ↔ параметр `name`).
- **Частковий набір параметрів:** не обов'язково передавати всі властивості в конструктор (наприклад, `Id` зазвичай не передається — EF Core встановить його через властивість після створення об'єкта).
- **Модифікатори доступу:** конструктор може бути `public`, `internal`, `protected` або навіть `private`.
- **Кілька конструкторів:** клас може мати декілька перевантажених конструкторів; EF Core обере найбільш підходящий.
- **Обмеження навігаційних властивостей:** EF Core **НЕ підтримує** передачу навігаційних властивостей (пов'язаних сутностей, наприклад `Company`) через параметри конструктора — вони завжди встановлюються окремо.

## Ключові фрагменти коду

```csharp
public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public int Age { get; set; }
    public Company? Company { get; set; }

    public User(string name, int age)
    {
        Name = name;
        Age = age;
    }
}
```

## Особливості роботи в SQLite

- Логіка матеріалізації об'єктів через конструктори виконується повністю на стороні EF Core у пам'яті після отримання даних від провайдера, тому в SQLite вона працює ідентично іншим СУБД.

## Підсумок та підводні камені

- Якщо у вас є конструктор із параметром, назва якого **не збігається** з жодною властивістю (або тип відрізняється), і при цьому немає конструктора без параметрів, EF Core викине виняток під час побудови моделі (`InvalidOperationException: No suitable constructor found`).
- Для підтримки інкапсуляції та nullable reference types зручно робити `private` конструктор без параметрів або параметризований конструктор для обов'язкових полів.
