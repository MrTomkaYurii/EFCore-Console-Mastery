## Мета уроку

Розібратися, за якими правилами EF Core включає класи C# до моделі бази даних, як коректно оголошувати `DbSet<T>` з увімкненими nullable reference types, а також як явно включати або виключати типи сутностей із моделі.

## Теоретичний матеріал

### Способи включення сутності в модель

EF Core додає клас до моделі (і створює для нього таблицю в БД) у трьох випадках:
1. **Через `DbSet<T>` у контексті даних** — таблиця отримує ім'я властивості `DbSet` (наприклад, `Users`).
2. **Через навігаційну властивість** — якщо сутність із `DbSet` посилається на інший клас (наприклад, `User.Company`), то `Company` також потрапляє до моделі, навіть якщо `DbSet<Company>` немає. У такому разі таблиця називатиметься за іменем класу (`Company`).
3. **Явно через Fluent API** — виклик `modelBuilder.Entity<Country>()` у методі `OnModelCreating`.

### Nullable-типи посилань (NRT) та `DbSet<T>`

Починаючи з .NET 6 / C# 10 у проєктах типово увімкнено `<Nullable>enable</Nullable>`. Оголошення `public DbSet<User> Users { get; set; }` без ініціалізації викликає попередження компілятора `CS8618`. Є два ідіоматичні способи уникнути його:
- `public DbSet<User> Users { get; set; } = null!;`
- `public DbSet<User> Users => Set<User>();` (рекомендований компактний варіант).

### Виключення сутності з моделі

Якщо клас використовується лише в пам'яті або є частиною іншої моделі, але не повинен мати таблиці в БД:
- **Анотація `[NotMapped]`** над класом.
- **Fluent API:** `modelBuilder.Ignore<AuditLog>();` в `OnModelCreating`.

## Ключові фрагменти коду

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    // Явне включення сутності без DbSet
    modelBuilder.Entity<Country>();

    // Повне виключення сутності з моделі
    modelBuilder.Ignore<AuditLog>();
}
```

## Особливості роботи в SQLite

- Усі механізми включення та виключення сутностей працюють на рівні побудови метаданих моделі EF Core (до генерації SQL), тому поведінка в SQLite повністю ідентична SQL Server.
- У демонстрації ми запитуємо системну таблицю `sqlite_master`, щоб наочно перевірити, які саме таблиці були створені в базі даних.

## Підсумок та підводні камені

- Якщо у сутності є навігаційна властивість на інший клас, EF Core автоматично «підтягне» його в модель — це часто призводить до неочікуваної появи зайвих таблиць, якщо забути поставити `[NotMapped]` або `Ignore<T>()`.
- Для доступу до сутності, включеної без `DbSet<T>` (через `modelBuilder.Entity<T>()`), у коді можна використовувати метод `db.Set<T>()`.
