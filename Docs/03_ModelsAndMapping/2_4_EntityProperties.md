## Мета уроку

Дізнатися, які властивості C#-класу EF Core автоматично включає до таблиці бази даних, як виключати непотрібні властивості, а також як працюють властивості з явними полями (backing fields) замість автовластивостей.

## Теоретичний матеріал

За замовчуванням до моделі включаються **всі публічні властивості** сутності, які відкриті як для читання (`get`), так і для запису (`set`). Властивості лише для читання (наприклад, обчислювані в C# `public string Summary => ...`) ігноруються.

### Виключення властивості з моделі

Якщо властивість потрібна в C#-коді (наприклад, як тимчасовий кеш або токен сесії), але для неї не потрібно створювати стовпець у БД:

- **Fluent API:** `modelBuilder.Entity<User>().Ignore(u => u.Address);`
- **Анотація даних:** атрибут `[NotMapped]` над властивістю.

### Використання полів класу (Backing Fields)

Властивість не обов'язково має бути автовластивістю `{ get; set; }`. Вона може мати повноцінні блоки `get` і `set`, які звертаються до приватного поля — наприклад, для нормалізації даних (`value.Trim()`) або валідації. EF Core коректно працює з такими властивостями.

## Ключові фрагменти коду

```csharp
public class User
{
    private string _name = string.Empty;

    public int Id { get; set; }
    public string Name
    {
        get => _name;
        set => _name = value.Trim();
    }

    [NotMapped]
    public string? SessionToken { get; set; }
}
```

## Особливості роботи в SQLite

- Механізм включення та виключення властивостей працює однаково для всіх провайдерів EF Core, включно з SQLite.
- У таблиці `Users` у SQLite створюються лише стовпці `Id`, `Name` та `Age`; для `Address`, `SessionToken` і `Summary` стовпці не створюються.

## Підсумок та підводні камені

- Виключені властивості (`[NotMapped]` або `Ignore()`) не можна використовувати в LINQ-запитах до БД (наприклад, `db.Users.Where(u => u.Address == "...")` призведе до помилки трансляції в SQL).
- Якщо властивість має `private set`, EF Core все одно може включати її в модель, але обчислювані властивості без `set` (expression-bodied) ігноруються.
