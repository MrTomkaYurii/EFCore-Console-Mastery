# 3.1. Зовнішні ключі та навігаційні властивості

- **Глава:** 04. Відносини між моделями
- **Оригінал на Metanit:** [https://metanit.com/sharp/efcore/3.1.php](https://metanit.com/sharp/efcore/3.1.php)

## Мета уроку

Зрозуміти, як у Entity Framework Core моделюються зв'язки між сутностями за допомогою зовнішніх ключів (Foreign Keys) та навігаційних властивостей (Navigation Properties), а також як розрізняти головну (principal) і залежну (dependent) сутності.

## Теоретичний матеріал

Для зв'язування моделей у EF Core використовуються два взаємодоповнювальні механізми:

- **Навігаційна властивість (Navigation Property)** — властивість C#-класу, яка посилається на іншу сутність (посилальна навігація, наприклад `Company? Company`) або на колекцію пов'язаних сутностей (колекційна навігація, наприклад `List<User> Users`).
- **Зовнішній ключ (Foreign Key, FK)** — скалярна властивість у залежній сутності, значення якої відповідає первинному ключу (Primary Key) головної сутності.

### Головна та залежна сутності

| Поняття | Опис | Приклад |
|---|---|---|
| **Головна сутність (Principal)** | Містить первинний ключ, на який посилаються інші таблиці; може існувати незалежно. | `Company` (`Id`, `Name`, `Users`) |
| **Залежна сутність (Dependent)** | Містить зовнішній ключ, що посилається на головну сутність. | `User` (`Id`, `Name`, `CompanyId`, `Company`) |

### Конвенції іменування зовнішнього ключа

За замовчуванням EF Core автоматично розпізнає властивість як зовнішній ключ, якщо її назва відповідає одному з шаблонів:

1. `<Ім'я_навігаційної_властивості><Ім'я_ключа_пов'язаної_сутності>` (наприклад, `Company` + `Id` = `CompanyId`).
2. `<Ім'я_класу_пов'язаної_сутності><Ім'я_ключа_пов'язаної_сутності>` (наприклад, `Company` + `Id` = `CompanyId`).

### Два способи встановлення зв'язку в коді

- **Через навігаційну властивість:** `user.Company = google;` — EF Core автоматично заповнить `CompanyId` після збереження `Company`.
- **Через зовнішній ключ:** `user.CompanyId = microsoft.Id;` — зручно, коли головна сутність уже є в БД і нам відомий лише її `Id`.

## Ключові фрагменти коду

```csharp
public class Company
{
    public int Id { get; set; }
    public string? Name { get; set; }
    public List<User> Users { get; set; } = new();
}

public class User
{
    public int Id { get; set; }
    public string? Name { get; set; }
    public int CompanyId { get; set; }      // Зовнішній ключ за конвенцією
    public Company? Company { get; set; }   // Навігаційна властивість
}
```

```csharp
// 1. Встановлення зв'язку через навігаційну властивість
var tom = new User { Name = "Tom", Company = google };

// 2. Встановлення зв'язку через зовнішній ключ
var kate = new User { Name = "Kate", CompanyId = microsoft.Id };
```

## Особливості роботи в SQLite

- У SQLite зовнішні ключі створюються безпосередньо в `CREATE TABLE` за допомогою `CONSTRAINT "FK_Users_Companies_CompanyId" FOREIGN KEY("CompanyId") REFERENCES "Companies"("Id") ON DELETE CASCADE`.
- На відміну від SQL Server, у SQLite перевірка зовнішніх ключів (`PRAGMA foreign_keys = ON;`) історично може бути вимкнена на рівні окремих утиліт, проте провайдер `Microsoft.EntityFrameworkCore.Sqlite` автоматично вмикає її для кожного з'єднання.
- Тип `int` у C# відображається в `INTEGER NOT NULL` у SQLite, а `string?` — у `TEXT`.

## Підсумок та підводні камені

- Якщо зовнішній ключ має тип `int` (не nullable), зв'язок вважається **обов'язковим**, і за замовчуванням у БД створюється `ON DELETE CASCADE`.
- Якщо ви встановлюєте зв'язок через `CompanyId`, а навігаційна властивість `Company` залишається `null`, у поточному контексті вона автоматично підтягнеться, якщо `Company` уже відстежується контекстом, або потребуватиме `Include()` у новому контексті.
- Наявність скалярної властивості `CompanyId` у моделі не є суворо обов'язковою (EF Core може створити тіньову властивість — shadow property), але явне оголошення FK значно спрощує фільтрацію та оновлення зв'язків.
