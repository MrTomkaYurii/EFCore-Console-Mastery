# 3.3. Завантаження пов'язаних даних. Метод Include

## Мета уроку

Опанувати стратегію **жадного завантаження (Eager Loading)** у EF Core за допомогою методів `Include()` та `ThenInclude()` для отримання зв'язаних сутностей за один SQL-запит.

## Теоретичний матеріал

За замовчуванням EF Core **не завантажує** навігаційні властивості — вони залишаються `null` (або порожніми колекціями), якщо пов'язані об'єкти ще не перебувають у поточному `DbContext`.

У EF Core існують три стратегії завантаження пов'язаних даних:

| Стратегія | Механізм | Коли застосовувати |
|---|---|---|
| **Eager Loading (жадне)** | `Include()` / `ThenInclude()` | Коли заздалегідь відомо, які пов'язані дані потрібні в запиті |
| **Explicit Loading (явне)** | `Load()` / `Collection()` / `Reference()` | Коли пов'язані дані потрібні вибірково після аналізу головної сутності |
| **Lazy Loading (ліниве)** | `UseLazyLoadingProxies()` + `virtual` | Коли зручно підвантажувати дані «на льоту» (обережно з проблемою N+1) |

### Як працюють `Include` та `ThenInclude`

- `Include(u => u.Company)` — завантажує пов'язану сутність першого рівня (у SQL це `LEFT JOIN` для необов'язкових зв'язків або `INNER JOIN` для обов'язкових).
- `ThenInclude(c => c!.Country)` — завантажує вкладені навігаційні властивості наступного рівня (глибше по ланцюжку зв'язків).
- Можна викликати `Include()` кілька разів в одному запиті для різних гілок (наприклад, `.Include(u => u.Company)` і `.Include(u => u.Position)`).

### Важливий нюанс: кеш контексту (Relationship Fix-up)

Якщо пов'язані сутності (наприклад, усі `Companies`) вже були завантажені або додані в поточний екземпляр `DbContext` раніше, EF Core автоматично «зшиє» навігаційні властивості без виклику `Include()`. Проте в новому `DbContext` без `Include()` вони будуть `null`.

## Ключові фрагменти коду

```csharp
// Багаторівневе жадне завантаження: User -> Company -> Country та User -> Position
var users = db.Users
    .Include(u => u.Company)
        .ThenInclude(c => c!.Country)
    .Include(u => u.Position)
    .ToList();
```

```csharp
// Зворотне завантаження колекції: Company -> Users
var companies = db.Companies
    .Include(c => c.Users)
    .ToList();
```

## Особливості роботи в SQLite

- Для запиту з `Include` провайдер SQLite генерує `LEFT JOIN` (якщо FK nullable) або `INNER JOIN` (якщо FK non-nullable).
- Якщо в одному запиті використовується кілька `Include()` на **колекції** (`List<T>`), у SQL це може призвести до так званого *Cartesian Explosion* (декартового добутку). У EF Core для уникнення дублювання великих обсягів даних можна використовувати `.AsSplitQuery()`, яке розіб'є запит на кілька окремих `SELECT`-ів — це повністю підтримується в SQLite.

## Підсумок та підводні камені

- Завжди перевіряйте, чи не забули ви `Include()`, коли передаєте сутності у новий `DbContext` або поза його межі.
- Не завантажуйте через `Include()` зайві рівні, якщо вам потрібні лише 1–2 поля — у таких випадках краще використати проєкцію `.Select(u => new { u.Name, CompanyName = u.Company!.Name })`, яка автоматично виконає потрібний `JOIN` без завантаження зайвих стовпців і без необхідності писати `Include()`.
