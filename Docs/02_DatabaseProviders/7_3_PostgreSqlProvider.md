# 7.3. Провайдер PostgreSQL (та адаптація під SQLite)

- **Глава:** 02. Провайдери баз даних
- **Оригінал на Metanit:** [https://metanit.com/sharp/efcore/7.3.php](https://metanit.com/sharp/efcore/7.3.php)
- **Код прикладу:** [Lesson_7_3_PostgreSqlProvider.cs](../../src/02_DatabaseProviders/Lesson_7_3_PostgreSqlProvider.cs)

## Мета уроку

Навчитися підключати Entity Framework Core до **PostgreSQL** за допомогою провайдера `Npgsql.EntityFrameworkCore.PostgreSQL`, розібрати структуру рядка підключення, команди міграцій та зворотного проєктування (`Scaffold-DbContext`), а також порівняти діалект PostgreSQL із SQLite на практиці.

## Теоретичний матеріал

### 1. Встановлення провайдера Npgsql

Для роботи з PostgreSQL використовується офіційний високопродуктивний провайдер **Npgsql**:

```bash
dotnet add package Npgsql.EntityFrameworkCore.PostgreSQL
```

### 2. Рядок підключення (Connection String)

Типовий рядок підключення для методу `UseNpgsql(...)`:

```text
Host=localhost;Port=5432;Database=usersdb;Username=postgres;Password=пароль_от_postgres
```

| Параметр | Значення у прикладі | Призначення |
| :--- | :--- | :--- |
| `Host` | `localhost` | Адреса сервера PostgreSQL. |
| `Port` | `5432` | Порт (стандартний порт PostgreSQL — `5432`). |
| `Database` | `usersdb` | Назва бази даних. |
| `Username` | `postgres` | Ім'я користувача (суперкористувач за замовчуванням — `postgres`). |
| `Password` | `...` | Пароль користувача. |

### 3. Міграції та підключення до існуючої БД (Reverse Engineering)

У параграфі 7.3 на Metanit також показані два базові сценарії роботи з інструментарієм `Microsoft.EntityFrameworkCore.Tools` (або `dotnet ef`):

1. **Міграції (Code First)**:
   - Встановлення пакета `Microsoft.EntityFrameworkCore.Tools`.
   - Створення міграції: `Add-Migration Initial` (або `dotnet ef migrations add Initial`).
   - Застосування до БД: `Update-Database` (або `dotnet ef database update`).
2. **Підключення до наявної БД (Database First / Scaffolding)**:
   - Генерація моделей і `DbContext` зі схеми PostgreSQL:
     ```powershell
     Scaffold-DbContext "Host=localhost;Port=5432;Database=usersdb;Username=postgres;Password=123456789" Npgsql.EntityFrameworkCore.PostgreSQL
     ```

## Ключові фрагменти коду

### Конфігурація для PostgreSQL (як на Metanit)

```csharp
using Microsoft.EntityFrameworkCore;

public class ApplicationContext : DbContext
{
    public DbSet<User> Users { get; set; } = null!;

    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        optionsBuilder.UseNpgsql(
            "Host=localhost;Port=5432;Database=usersdb;Username=postgres;Password=пароль_от_postgres");
    }
}
```

### Демонстрація запиту та `ToQueryString()` у цьому проєкті (SQLite)

```csharp
var query = db.Users
    .Where(u => u.Name != null && EF.Functions.Like(u.Name, "T%"))
    .OrderBy(u => u.Id);

Console.WriteLine(query.ToQueryString());
```

## Особливості роботи в SQLite

SQLite та PostgreSQL мають схожий синтаксис екранування ідентифікаторів (подвійні лапки `"Users"`), проте суттєво відрізняються в деталях:

| Аспект | PostgreSQL (`UseNpgsql`) | SQLite (`UseSqlite`) |
| :--- | :--- | :--- |
| Чутливість ідентифікаторів у лапках | `"Users"` — **суворо чутливі до регістру** | Нечутливі до регістру імен таблиць/колонок |
| Автоінкремент PK | `GENERATED BY DEFAULT AS IDENTITY` (або `SERIAL`) | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| Пошук за шаблоном без регістру | Вбудований оператор `ILIKE` (`EF.Functions.ILike`) | Стандартний `LIKE` (для ASCII нечутливий до регістру) |
| Типи `DateTime` | `timestamp with time zone` (вимагає `DateTimeKind.Utc` у Npgsql 6+) | Зберігається як `TEXT` у форматі ISO-8601 |

## Підсумок та підводні камені

- **Часові пояси в Npgsql**: починаючи з Npgsql 6.0, `DateTime` із `DateTimeKind.Local` або `Unspecified` не можна записувати в колонку `timestamp with time zone` без явного перетворення в UTC (`.ToUniversalTime()` або використання `DateTimeOffset`).
- **Регістр імен у PostgreSQL**: якщо таблиці створювалися вручну без лапок, PostgreSQL зберігає їх у нижньому регістрі (`users`), тоді як EF Core за замовчуванням генерує `"Users"`. Для автоматичного перетворення в `snake_case` у PostgreSQL часто використовують пакет `EFCore.NamingConventions`.
- **Логіка доступу до даних лишається незмінною**: завдяки абстракції `DbContext` перехід між SQLite для локальної розробки та PostgreSQL у продакшені зводиться до зміни провайдера в `DbContextOptions`.
